# Data model: Frontend inventory stock movements

The frontend consumes backend entities and keeps only interaction state in memory. It does not calculate or persist authoritative stock changes.

## Inventory part

| Field | UI meaning | Rule |
|---|---|---|
| `id` | Stable numeric article identifier | Required for movement operations. |
| `code` / `sku` | Human-facing inventory code | Existing catalog CRUD continues to use SKU. |
| `name`, `category`, `description` | Catalog attributes | Edited in the catalog form. |
| `unit_price`, `minimum_threshold` | Price and alert threshold | Preserve existing exact money/threshold handling. |
| `current_stock` / `stock` | Authoritative current balance | Display only in normal edit; update after a confirmed movement response or refreshed inventory response. |
| `active` | Catalog visibility | The list endpoint returns active items; retired items may remain addressable through a history route by ID. |

## Movement record

| Field | Display/use |
|---|---|
| `id` | Stable row key and pagination identity. |
| `part_id` | Numeric article relation; can be null for preserved records after physical deletion. |
| `code_snapshot`, `name_snapshot` | Article labels captured at movement time. |
| `movement_type` | `OPENING_BALANCE`, `ADJUSTMENT_IN`, `ADJUSTMENT_OUT`, `PURCHASE_RECEIPT`, or `SALE`; translate labels in Spanish. |
| `quantity_delta` | Signed change; display a plus sign for entries and minus for exits. |
| `stock_before`, `stock_after` | Authoritative balance before and after the movement. |
| `reason` | Optional for historic purchase/sale/legacy rows; show only if present. |
| `actor_kind`, `actor_user_id`, `actor_name` | Source/responsible identity as supplied; do not invent a user when missing. `SYSTEM` means system-generated opening at cutover. |
| `created_at` | Effective application timestamp. |
| `source_type`, `source_id` | Purchase receipt or sale link when present; manual/opening movements may not have a document source. |
| `is_before_cutover` | Marks movement history preceding the new stock baseline. |

## Opening/adjustment draft

| Field | Rule |
|---|---|
| `counted_stock` | Integer from 0 to 999999, representing the physical count; never a delta or requested final server balance. |
| `reason` | Required, 1 to 500 characters after trimming. |
| `Idempotency-Key` | UUID for one operation. Retain with its payload for retries; generate a new key for a new action. |
| `request_hash` | Generated by backend from operation, article ID and payload; the frontend does not send or calculate it. |

## Client-side operation state

`idle → submitting → confirmed | no-change | recoverable-error`. A confirmed result updates the displayed article from the backend response. A conflict or transport error leaves the previous balance untouched. An opening that fails after article creation leaves a server-side article at zero and a retryable opening draft tied to that article ID.

## History query

Query state consists of `movement_type`, `from_date`, `to_date`, `limit` (default 50, maximum 200) and `offset`. Backend order is descending by creation time and movement ID. A filter or page change starts a new loading state; empty results are a valid state.
